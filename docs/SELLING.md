# Selling this & earning GitHub stars — honest guidance

You said two goals: **sell it** and **earn stars on GitHub**. These pull in
opposite directions; pick a model deliberately.

## The tension
- **Stars** come from things being *free, open, and useful*. Closed/paid repos
  get almost no stars.
- **Direct sales** need something *gated* (code, support, hosting, pro modules).

You cannot maximize both with the same artifact. The proven pattern is
**open-core**.

## Realistic models (ranked)
1. **Open-core (recommended).** MIT core (this repo) earns stars and trust;
   sell paid add-ons: premium provider packs, the agent brain, hosted runs,
   priority support, "done-for-you" setup. Stars become your top-of-funnel.
2. **Paid template/boilerplate.** Sell a polished version on Gumroad / Lemon
   Squeezy / Polar. Keep a lite version public for stars. Works if the docs +
   UX are exceptional.
3. **Sponsorware.** Public repo, GitHub Sponsors; new pro features unlock for
   sponsors then graduate to open. Good for steady small income + stars.
4. **Services on top.** The repo is the lead magnet; you sell setup,
   customization, and managed operation.

GitHub itself has **no paid-repo store** — money happens via the above, not by
"listing the repo for sale."

## What actually earns stars (do these)
- A killer README: 1-line hook, GIF/screenshot, 60-second quickstart.
- It must work in <5 min: the `--dry-run` path already does this — lead with it.
- Real screenshots of the dashboard + Studio (add to README).
- A live demo (GitHub Pages dashboard is already deployable — link it).
- Trust signals: CI badge, tests, LICENSE, CHANGELOG, SECURITY.md (all present).
- A sharp niche story, not "does everything" — "config-driven, free,
  self-hosted content automation with an agentic core."
- Launch where builders are (Show HN, r/selfhosted, Product Hunt, X) with the
  demo link.

## Before you charge anyone (protect yourself)
- Keep the **safety gate** on for any content workflow; ship the disclaimer in
  LICENSE. Auto-generated kids content is a liability category.
- Never advertise guaranteed revenue/views — market it as a time-saving
  engine.
- Make unattended bulk posting clearly the operator's responsibility under the
  target platform's ToS.
- Offer "as-is, community support" for free tier; paid tier = defined support.

## Honest readiness gate
Do not charge until P0 in `docs/ASSESSMENT.md` is done (tests ✓, budget
breaker ✓, safety gate ✓, license ✓ — now complete) **and** the README has
screenshots + a live demo link. At that point it is a credible paid open-core
product; before that it is an impressive prototype.
